# 覆盖式更新规则（当前遵守）

> 这份文件描述的是「MCDL Launcher 现在实际怎么做覆盖式更新」。
> 每次发版都必须照第 1 节把**所有位置**的版本号改齐，再按第 2~5 节打包、验证、快照、发布。
> `updates/backup.js` 会把这份文件自动复制进每个更新快照。

## 0. 一句话

覆盖式更新 = 只替换安装目录里的程序文件（`MCDL Launcher.exe`、`resources/app.asar`、
`resources/mcdl/mcdl.jar` 等），**不动** `%APPDATA%` 里的用户数据；每次发版必须同步所有位置的
版本号，并留下完整快照。

## 1. 版本号：必须同步的位置（重点）

版本号的**唯一来源**是 `electron/package.json` 的 `version`。其它地方能引用就引用，
不能引用才写死；写死的每一处都必须在下表里，发版时逐个检查。

| # | 位置 | 要改什么 | 怎么核对 |
| --- | --- | --- | --- |
| 1 | `electron/package.json` | `"version": "X.Y.Z"` | `node -e "console.log(require('./electron/package.json').version)"` |
| 2 | `electron/package-lock.json` | 顶层 `version` 和 `packages[""].version` 都要等于 X.Y.Z | `npm install --package-lock-only` 会自动同步；或手工改这两处 |
| 3 | `README.md` | 顶部 `vX.Y.Z · 内测包` 说明；`MCDL-Launcher-X.Y.Z-x64.zip`；`MCDL-Launcher-X.Y.Z-update.zip` / 文件夹名 | `git grep -n "0\.[0-9]*\.[0-9]*" README.md` |
| 4 | `electron/launch.js` | `-Dminecraft.launcher.version` 用的 `LAUNCHER_VERSION`（**现在从 package.json 读取，不要写死**） | `git grep -n "LAUNCHER_VERSION"` |
| 5 | `electron/modrinth.js` | Modrinth 的 `User-Agent` 版本（**现在从 package.json 读取，不要写死**） | `git grep -n "USER_AGENT"` |
| 6 | 面向用户的文档 | 如 `docs/troubleshooting.md` 里「X.Y.Z 起……」的版本说明 | `git grep -n -E "0\.[0-9]+\.[0-9]+" docs/` |
| 7 | 更新快照 `updates/<version>/` | 目录名、`manifest.json` 的 `name` / `packageVersion` / `releaseTag`、`CHANGELOG.md` 标题、产物名 | 看 `manifest.json` |
| 8 | 构建产物 | `dist/MCDL-Launcher-X.Y.Z-x64.zip`、`dist/MCDL-Launcher-X.Y.Z-update/` 与 `.zip`；exe 文件属性 `X.Y.Z` | `(Get-Item 'dist\win-unpacked\MCDL Launcher.exe').VersionInfo` |
| 9 | 提交与标签 | 提交信息 `release(vX.Y.Z)`，标签 `vX.Y.Z` | `git tag -l 'v*'` |

**发版前统一检查**：

```powershell
node -e "console.log(require('./electron/package.json').version)"
git grep -n -E "0\.[0-9]+\.[0-9]+" -- . ':!dist' ':!updates/*/' ':!docs/history' ':!docs/screenshots'
```

允许保留旧版本号的地方只有：历史文档（`docs/history/*`）、明确写「某版本实测」的代码注释、
测试里的版本比较样例。其它地方出现旧版本号一律视为漏改。

**本次 0.3.3 实际修掉的漏改**：`package-lock.json`（0.2.0）、`launch.js` 的
`-Dminecraft.launcher.version=0.2.0`、`modrinth.js` 的 `User-Agent .../0.2.0`。
后两处已改成从 `package.json` 读取，以后只需要改 package.json 与 lock。

## 2. 更新包（给已安装用户）的内容规则

目录名固定 `MCDL-Launcher-X.Y.Z-update`，结构与安装目录一致，用户解压后**全选复制**到启动器目录：

```
MCDL-Launcher-X.Y.Z-update/
  MCDL Launcher.exe          必须：exe 里带版本资源和 app.asar 完整性校验，和 asar 必须成对替换
  resources/app.asar         必须：程序本体
  resources/mcdl/mcdl.jar    只有 mcdl.jar 变了才必须；没变也建议带上，兼容跨版本覆盖
  README-update.txt          必须：复制步骤 + 本次更新内容 + 版本号
```

规则：

- **不带** `resources/jre`（内置 JRE 没变时）、`locales/`、DLL / pak（Electron 版本没变时）。
- **Electron 版本变了**（看 `electron/package.json` 的 `electron`）就必须用完整包，
  或把整个 Electron 运行时一起打进更新包；只换 exe + asar 会和旧 DLL 不匹配。
- 更新包里不要放 `%APPDATA%` 数据、游戏目录、日志。
- 文件名用 ASCII（如 `README-update.txt`）：Windows 资源管理器解压 zip 时，非 ASCII 名字
  可能因为没有 UTF-8 名字标志而乱码。
- 更新包必须实测：在**上一个发布版本**的完整目录上覆盖，确认 `app:info` 版本、核心功能正常。

## 3. 构建与校验

```powershell
cd electron
npm run dist        # 或：.\node_modules\.bin\electron-builder.cmd --win zip --x64
```

构建完成后：

1. `dist\win-unpacked\MCDL Launcher.exe` 的文件属性版本 = X.Y.Z；
2. 从 `win-unpacked` 组装更新目录（exe + `resources/app.asar` + `resources/mcdl/mcdl.jar` + `README-update.txt`）；
3. 校验 `win-unpacked` / 更新目录 / zip 内条目三者一致（app.asar 与 exe 的 SHA-256 相同）；
4. 压缩更新目录：`tar -a -cf dist\MCDL-Launcher-X.Y.Z-update.zip -C dist MCDL-Launcher-X.Y.Z-update`；
5. 记录两个 zip 的字节数与 SHA-256。

## 4. 快照与记录

```powershell
node updates/backup.js X.Y.Z --base v<上一个已发布版本>
```

- 基线默认取最近 tag；脚本用 `git diff <base>` + 未跟踪文件列出改动并复制到 `files/`；
- 脚本会把本规则文件复制到 `updates/X.Y.Z/覆盖式更新规则.md`；
- 手动补 `CHANGELOG.md`：新功能 / 动效 UI / 修复 / 设置 / 验证 / 发布物；
- 手动补 `manifest.json`：`releaseCommit`、`releaseTag`、`tests.total/passed`、
  `artifact`（完整包）与 `updatePackage`（更新包）的 name / size / sha256 / contents。

## 5. 发布

1. 提交：`release(vX.Y.Z): 一句话`；
2. 打标签：`git tag -a vX.Y.Z -m "..."`；
3. 推送：`git push origin main` + `git push origin vX.Y.Z`；
4. 上传 `MCDL-Launcher-X.Y.Z-x64.zip`（新装）和 `MCDL-Launcher-X.Y.Z-update.zip`（覆盖更新）；
5. 当前没有自动更新（`electron-builder.yml` 的 publish 段是注释掉的，不出 `latest.yml`），
   不要声称支持自动更新。

**如果推送后才发现版本号漏改**：

- 发布几分钟内、还没分发：修正后 `git commit --amend`，`git tag -f` 移动标签，
  `git push --force-with-lease origin main`、`git push --force origin vX.Y.Z`，并重建产物、更新快照；
- 已经分发：**不要改已发布的标签和 zip**，改为发下一个版本号（如 0.3.4），在 CHANGELOG 写明修正。

## 6. 发版检查清单

- [ ] `package.json` 版本 = X.Y.Z
- [ ] `package-lock.json` 两处版本 = X.Y.Z
- [ ] README 顶部 / 完整包名 / 更新包名 = X.Y.Z
- [ ] `launch.js` / `modrinth.js` 没有写死版本（从 package.json 读取）
- [ ] 面向用户的文档版本说明已更新
- [ ] 全量测试通过（`node --test --test-isolation=none tests/*.test.js`）
- [ ] 完整包 + 更新包已构建，exe 文件属性 = X.Y.Z
- [ ] 更新包在上一版本目录上覆盖实测通过
- [ ] 三个位置的 app.asar / exe SHA-256 一致
- [ ] `updates/X.Y.Z/` 快照 + CHANGELOG + manifest（含两个产物的 SHA-256）
- [ ] 提交 `release(vX.Y.Z)` + 标签 `vX.Y.Z` + push
- [ ] 两个 zip 已上传
